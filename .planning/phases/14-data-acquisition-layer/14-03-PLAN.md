Create apps/web/src/lib/tikhub/adapters/xiaohongshu.ts implementing all five PlatformAdapter methods using TikHub XHS endpoints.

## Method: resolveUrl(url: string): Promise<string>

Endpoint: GET /api/v1/xiaohongshu/app/get_user_id_and_xsec_token
Params: { url }
Response data shape: { user_id: string, xsec_token: string }
Returns: data.user_id

Note: Store xsec_token is returned by TikHub but not needed for subsequent calls in this adapter — ignore it.

## Method: fetchAccount(userId: string): Promise<NormalizedAccount>

Endpoint: GET /api/v1/xiaohongshu/app_v2/get_user_info
Params: { user_id: userId }
Response data shape: { user_id, nickname, avatar, desc, follows, fans, interaction, tag_list: Array<{ name }> }

Map to NormalizedAccount:
- platformUserId: data.user_id
- nickname: data.nickname ?? ''
- avatar: data.avatar ?? ''
- signature: data.desc ?? ''
- followerCount: Number(data.fans) ?? 0
- followingCount: Number(data.follows) ?? 0
- totalLikes: Number(data.interaction) ?? 0  // XHS "获赞与收藏" count
- videoCount: 0  // XHS does not expose note count in profile API; downstream will use fetchVideos length
- isVerified: Array.isArray(data.tag_list) && data.tag_list.length > 0
- verifyInfo: data.tag_list?.[0]?.name ?? ''

## Method: fetchVideos(userId: string, count: number): Promise<NormalizedVideo[]>

Endpoint: GET /api/v1/xiaohongshu/app_v2/get_user_posted_notes
Params: { user_id: userId, cursor: '' (initial empty string), num: 20 }
Pagination: response data has { notes: [...], cursor: string, has_more: boolean }

Pagination logic:
- Accumulate notes in a results array
- Continue fetching while results.length < count AND data.has_more === true
- Pass data.cursor as cursor in next request (string cursor, not numeric)
- Page size: 20 per request
- Hard cap: stop when results.length >= count OR has_more is false

Map each note in data.notes to NormalizedVideo:
- videoId: item.note_id
- title: item.display_title ?? item.title ?? ''
- coverUrl: item.cover?.url ?? item.cover?.url_default ?? ''
- videoUrl: ''  // XHS notes API does not return video URL directly; left empty
- createTime: item.time  // Unix timestamp in seconds
- duration: 0  // XHS notes API does not include duration; use 0
- views: 0  // Notes list API does not include view count; use 0 (fetchVideoStats will fill this)
- likes: item.interact_info?.liked_count ?? 0
- comments: item.interact_info?.comment_count ?? 0
- shares: item.interact_info?.share_count ?? 0
- collects: item.interact_info?.collected_count ?? 0

Return results.slice(0, count).

## Method: fetchVideoStats(videoIds: string[]): Promise<Map<string, VideoStats>>

Endpoint: GET /api/v1/xiaohongshu/web_v2/fetch_feed_notes_v2
Params: { note_ids: videoIds.join(',') }

Note: XHS does not have a batch stats endpoint like Douyin. This endpoint fetches note detail for each note ID. TikHub accepts a comma-separated list of note_ids.

Response data shape: { notes: Array<{ note_id, interact_info: { viewed_count, liked_count, comment_count, shared_count, collected_count } }> }

Build Map<string, VideoStats> keyed by note_id:
- views: item.interact_info?.viewed_count ?? 0
- likes: item.interact_info?.liked_count ?? 0
- comments: item.interact_info?.comment_count ?? 0
- shares: item.interact_info?.shared_count ?? 0
- collects: item.interact_info?.collected_count ?? 0

If videoIds is empty, return empty Map immediately.
Process in batches of 20 if videoIds.length > 20 (XHS API limit is lower than Douyin).

## Method: fetchComments(videoId: string, count: number): Promise<NormalizedComment[]>

Endpoint: GET /api/v1/xiaohongshu/app_v2/get_note_comments
Params: { note_id: videoId, cursor: '' }
Response data shape: { comments: Array<{ id, content, like_count, create_time, pinned }> }

Map each comment:
- commentId: item.id
- text: item.content ?? ''
- likes: item.like_count ?? 0
- createTime: item.create_time  // Unix timestamp in seconds
- isTop: item.pinned === true

Single page only (no pagination for comments).
Return results.slice(0, count).

## Type safety

Define internal wire types as private interfaces within the file (not exported) for TikHub XHS response shapes. Use optional chaining for all nested field access.

## Error handling

Do not catch errors in adapter methods — let TikHubError propagate up to the pipeline (Phase 15 handles failures).
