```typescript
import type { Platform } from './types'

export interface ParsedUrl {
  platform: Platform
  rawUserId: string | null  // extracted from URL path; may need resolveUrl() for final platformUserId
}
```

Implement detectPlatform(url: string): Platform | null:
- Lowercase the URL before matching
- Return 'douyin' if url contains 'douyin.com', 'iesdouyin.com', or 'v.douyin.com'
- Return 'xiaohongshu' if url contains 'xiaohongshu.com', 'xhslink.com', or 'xhs.cn'
- Return null for anything else (bilibili and kuaishou are deferred to Phase 2)
- Never throw — catch all URL parsing errors and return null

Implement extractUserId(url: string): string | null:
- Use URL constructor to parse the pathname
- Split pathname by '/' and filter empty strings
- For Douyin: look for the segment immediately after 'user' in the path (e.g., /user/MS4wLjABAAAA → 'MS4wLjABAAAA')
- For Xiaohongshu: look for the segment immediately after 'profile' in the path (e.g., /user/profile/abc123 → 'abc123')
- Return null if the expected path segment is not found or the URL is unparseable
- Never throw

Implement parseUrl(url: string): ParsedUrl | null:
- Calls detectPlatform and extractUserId
- Returns null if platform is null
- Returns { platform, rawUserId } otherwise

Export: detectPlatform, extractUserId, parseUrl, ParsedUrl

Note: rawUserId from URL path is a starting hint. Douyin URLs often contain sec_user_id directly in the path; XHS URLs contain the user_id. The adapter's resolveUrl() handles cases where the URL contains only a share token and a TikHub API call is needed to resolve the real ID.
