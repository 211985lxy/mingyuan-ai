<objective>
Add a schemaVersion field to PexelsQueryCache so that when relevance scoring is deployed in Phase 3, pre-scoring cached results are treated as cache misses instead of silently bypassing the scorer.

Purpose: Without schema versioning, cache hits return pre-scoring result sets that were never filtered. After Phase 3 adds scoring, old cache entries would bypass it entirely. Adding schemaVersion now (before scoring exists) means the version can be incremented when scoring deploys, forcing fresh fetches that go through the scorer.

Output: Prisma migration adding schemaVersion column, computeQueryHash functions updated to include version in hash, all cache read/write sites in route.ts updated.
</objective>

- A query cached at version 1 produces hash `abc123`
- The same query at version 2 produces hash `def456` (different hash)
- Looking up by `queryHash` at version 2 naturally misses the version 1 entry

- Old cache entries become dead rows (can be cleaned up later) but cause no correctness issues
