<objective>
Create the two-tier relevance scoring module and abstract fallback generator as a standalone library.

Purpose: This is the core scoring logic that gates stock media quality. Tier 1 (deterministic keyword intersection) runs at zero LLM cost. Tier 2 (LLM batch scoring) triggers only when Tier 1 yield is below 50%. Abstract fallback fills remaining slots with tone-appropriate generic visuals when scored candidates are insufficient.

Output: `material-relevance.ts` with exported scoring and fallback functions, updated `MaterialAssignment` type with `quality` field, and comprehensive unit tests validating all five requirements.

Implement `scoreDeterministic(row, businessKeywords, archetype)`:
- Concatenate `row.alt ?? ""` lowercased as the text signal.
- Derive businessKeywords from `archetype.split(" ")` plus `entry.query.split(" ")`, lowercased, deduplicated, filtered to length >= 3 (skip short words like "a", "of").
- If archetype !== GENERIC_ARCHETYPE: check if any OFF_DOMAIN_TERMS appear in text AND businessOverlap === 0 --> reject with score 0.
- Compute overlapRatio = businessKeywords found in text / total businessKeywords. Score = round(overlapRatio * 100).
- Return `{ score, rejected: false }` (deterministic never rejects on score alone -- it only hard-rejects on off-domain + zero overlap).

Implement `scoreLLMBatch(rows, context, entry)`:
- Use `LLMClient.shared()`. If `!llm.available`, return all rows as un-scored (score=50, rejected=false, tier="llm").
- Build system prompt (in Chinese, matching project convention):
```
你是一名图库素材相关性评估专家。
给定用户的业务背景和一批图库素材的描述，为每条素材评分（0-10），判断是否与用户的具体行业相关。

评分标准：
- 9-10：高度相关，直接展示用户行业的典型场景
- 6-8：相关，展示的内容符合用户业务方向
- 3-5：边缘相关，通用商业场景，非行业特定
- 0-2：不相关，展示了与用户行业无关的场景（如自然风景、其他行业）

输出 JSON：{"scores":[{"id":"pexels:123","score":7,"reject":false}]}
reject=true 当 score <= 5。
```
- User message: business context (industry, primaryOffer, targetAudience, max 300 chars of context) + array of candidates as `[{id: "provider:pexelsId", alt: row.alt}]`.
- Cap at 20 candidates per call.
- Parse JSON defensively: accept bare array, `parsed.scores`, or `parsed.results`.
- On parse failure or LLM error: return all candidates as un-scored (score=50, rejected=false).
- Model: `process.env.PACKAGING_MATERIAL_PLAN_MODEL || "openai/gpt-5.4-mini"`.
- Temperature: 0.2 (lower than query generation -- scoring needs consistency).
- maxTokens: 800 (scoring output is smaller than query planning).

Implement `scoreAndFilterMedia(rows, context, entry)`:
1. Derive businessKeywords from `context.archetype.split(" ")` + `entry.query.split(" ")`.
2. Run `scoreDeterministic` on all rows.
3. Count deterministic passes (not rejected). Compute acceptance rate = passes / total.
4. If acceptance rate < DETERMINISTIC_YIELD_THRESHOLD AND rows.length > 0:
   - Run `scoreLLMBatch` on the non-rejected rows from Tier 1.
   - For each LLM-scored row: if LLM score <= LLM_PASS_SCORE, mark rejected=true.
   - Return merged results (Tier 1 rejections + LLM-scored rows).
5. Else: return deterministic results as-is (all non-rejected pass through).
6. Sort accepted results by score descending.

Implement `INDUSTRY_ABSTRACT_QUERY_MAP` exactly as specified in RESEARCH.md Pattern 4 (all 21 entries including "professional service business" generic fallback).

Implement `generateAbstractFallbackMedia(entry, context, count)`:
- Look up `INDUSTRY_ABSTRACT_QUERY_MAP[context.archetype]`. If not found, use the "professional service business" entry.
- Get the abstract query for `entry.role`.
- Return an array of `{role, query, tone, count}` objects that the caller (route.ts) will use to call `loadMediaFromAllProviders()`. The caller marks these results with `quality: "generic"`.
- This function returns the query metadata, NOT the actual media rows (it cannot call loadMediaFromAllProviders because that is defined in route.ts).

Export signature:

  role: SafeRole,
  archetype: string,
): { query: string; tone: "warm" | "clean" }
