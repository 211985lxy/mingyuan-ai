# AiM 模型使用规范

> 适用范围：`明动aim智能体` 当前产品开发、AIM 智能体使用、客户方案输出、资料整理与日常排障。  
> 目标：别按“哪个模型最强”来选，按“任务类型 + 成本 + 推理强度”来配。

## 一句话原则

- 真写代码、真改功能、真排障：优先 `GPT-5.4`
- 做产品方案、定方向、写客户策划：优先 `GPT-5.5`
- 批量整理、清洗、改写、轻分析：优先 `GPT-5.4-mini`
- 推理程度默认用 `中`，不要把普通任务一上来就开 `高` 或 `超高`

## 推荐总表

| 场景 | 典型任务 | 推荐模型 | 推理程度 | 使用原因 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 日常功能开发 | 改页面、接接口、补状态、修交互 | `GPT-5.4` | `中` | 稳，贴代码，适合持续实现 | 默认开发档 |
| 复杂功能开发 | 跨模块改造、旧逻辑叠新能力、状态流复杂 | `GPT-5.4` | `高` | 更适合实现级推演，回归风险更低 | 复杂时再升高 |
| 疑难排障 | provider 异常、数据链路不通、历史记录丢失 | `GPT-5.4` | `高` | 更适合根因分析和排除假设 | `超高` 仅留给高代价故障 |
| 产品方案设计 | 新模块规划、功能边界、工作流设计、后台/前台归属 | `GPT-5.5` | `中` | 业务抽象和结构组织更强 | 先定方向，再让 `5.4` 落地 |
| 架构/策略问题 | agent 边界、方法论沉淀、系统分层、定价设计 | `GPT-5.5` | `高` | 适合做多因素权衡 | 产出方案后再实装 |
| 客户策划案 / IP 方案 | 主页四件套、操盘方案、定位策划、客户表达 | `GPT-5.5` | `中` | 中文商业表达和结构判断更强 | 公开表达先用它定调 |
| 口播稿 / 文案首稿 | 口播、标题、介绍、销售表达、老板人设文案 | `GPT-5.5` | `中` | 定调、抓重点、减少“AI味” | 适合先出母稿 |
| 批量改写 / 压缩 / 变体 | 一稿多版、精简、去 AI 味、转短版 | `GPT-5.4-mini` | `低` | 快，便宜，适合重复加工 | 基于 `5.5` 母稿二次处理 |
| 资料整理 / 入库 | 纪要整理、事实/观点拆分、标签化、Obsidian 入库 | `GPT-5.4-mini` | `低` | 规则型工作多，没必要高推理 | 混人物时升到 `5.4 + 中` |
| 轻分析 / 摘要 | 总结页面、提取要点、整理测试结果、生成日报草稿 | `GPT-5.4-mini` | `低` | 足够用，速度快 | 不负责最终业务判断 |
| 市场洞察 / 对标账号 | 对标池维护、爆款整理、监控数据转选题线索 | `GPT-5.4` | `中` | 要结合真实数据，不能飘 | 做策略判断时可切 `5.5 + 中` |
| AIM 方法论 / 路由 | prompt 设计、知识来源优先级、agent 分工 | `GPT-5.5` | `中/高` | 需要同时看业务目标和系统边界 | 定完后交给 `5.4` 实装 |

## 推理程度怎么用

| 推理程度 | 适用任务 | 是否默认 |
| --- | --- | --- |
| `低` | 整理、提取、改写、格式化、轻量总结 | 否 |
| `中` | 默认档，大多数开发和内容任务 | 是 |
| `高` | 架构设计、复杂实现、真实排障 | 否 |
| `超高` | 高代价复杂问题，且判断错一次很伤 | 否 |

## 结合当前 AiM 项目的直接建议

| 模块 / 工作 | 推荐模型 | 推理程度 | 说明 |
| --- | --- | --- | --- |
| `/competitor`、市场洞察、对标账号链路 | `GPT-5.4` | `中` | 要贴真实数据和代码，少幻觉 |
| AIM 方法论、智能体分工、产品路由 | `GPT-5.5` | `中/高` | 先定边界，再落代码 |
| 老板 IP、主页、口播、客户策划案 | `GPT-5.5` | `中` | 更适合中文商业表达 |
| 会议纪要清洗、素材入库、标签整理 | `GPT-5.4-mini` | `低` | 以效率优先 |
| 真实 bug、回归问题、provider 故障 | `GPT-5.4` | `高` | 适合做根因定位 |
| 一稿多版、文案精简、去 AI 味 | `GPT-5.4-mini` | `低` | 适合批量处理 |

## 默认使用规则

| 任务类型 | 默认配置 |
| --- | --- |
| 真写代码 | `GPT-5.4 + 中` |
| 做方案 | `GPT-5.5 + 中` |
| 写客户内容 | `GPT-5.5 + 中` |
| 批量整理 / 改写 | `GPT-5.4-mini + 低` |
| 真排障 | `GPT-5.4 + 高` |

## 不建议的用法

- 不要把普通资料整理、改写、摘录任务开成 `高` 或 `超高`
- 不要让 `mini` 直接做最终产品架构判断或复杂排障结论
- 不要让 `5.5` 长时间承担大批量重复清洗任务，成本不划算
- 不要让模型自己决定“是不是需要高推理”，先按任务类型手动分档

## 最后建议

如果只记一条，就记这个：
