# 通用短视频结构手册（V1）

## 这份文档解决什么问题

现有“结构”如果带有强烈行业属性，会把用户的思考路径锁死在某个行业话术里，结果是：

- 用户会误以为结构等于行业模板
- 结构很难跨行业复用
- 结构无法稳定映射到包装层和剪辑层

所以这一版重写的目标不是再写一套“行业脚本模板”，而是定义 10 套通用的短视频结构/拍摄手法。

这些结构必须同时满足 3 个条件：

1. 不带行业限制，任何行业都能套用
2. 能稳定影响文案“怎么讲”
3. 能向下游输出可适配的剪辑倾向，而不是只停留在文案层

## 调研后得出的 8 条共识

1. 短视频不是把长视频剪短，而是先确定“一个核心动作”和“一个核心情绪”。
2. hook 必须前置，前三秒和前一句决定留存。
3. 结构不是文案提纲而已，它还应该决定字幕密度、镜头切换、证据素材强度和节奏。
4. 短视频的镜头不一定复杂，但必须有明确的“注意力引导”。
5. 观众理解速度比创作者表达欲更重要，所以结构必须强约束“只保留精华”。
6. 很多高完成度短视频不是靠大制作，而是靠简单设定 + 准确节奏 + 明确转折。
7. 情绪和体验感常常比纯理性说服更有效，所以结构里必须允许“氛围”“共情”“反差”“惊喜”。
8. 当前产品里，BGM 只能先作为建议，不作为自动能力；真正能先落地的是模板推荐、参数预设和 Pexels 素材要求。

## 结构输出格式

从产品实现角度，每一套结构都应该输出这些字段：

- `文案骨架`：决定怎么讲
- `首屏机制`：决定前 1-3 秒怎么抓人
- `节奏倾向`：快 / 中 / 慢
- `字幕策略`：普通 / 强高亮 / 章节式 / 极简
- `证据密度`：弱 / 中 / 强
- `推荐素材角色`：优先需要哪些支持型素材
- `模板倾向`：更适合什么能力的包装模板
- `BGM 倾向`：只做手动建议，不自动控制

## 10 套通用结构

### 1. 反差钩子法

一句话理解：
先给观众一个和常识相反的句子或画面，让他停下来，再在后面完成解释。

文案骨架：
- 你以为 X
- 其实真正决定结果的是 Y
- 为什么大多数人会看错
- 你该怎么改
- CTA

首屏机制：
- 第一秒直接上反差句、反差动作或反差画面
- 不铺垫背景，不先自我介绍

节奏倾向：
- 快

字幕策略：
- 强高亮
- 反差词必须大字打出来，例如“不是”“恰恰相反”“真正的问题”

证据密度：
- 中

推荐素材角色：
- `product_detail`
- `process`
- 必要时加 1 个结果型画面

模板倾向：
- 适合标题栏强、字幕感强、节奏偏快的模板
- 更适合开场有强文案承载区的包装模板

BGM 倾向：
- 节奏推动型

对成片的影响：
- 开头更容易停留
- 字幕和节奏感会更强
- 成片更像“观点挑战”而不是普通说明

### 2. 悬念递延法

一句话理解：
先抛结果、问题或未完成动作，把答案延后 1-3 个节拍揭开。

文案骨架：
- 先抛一句未解释的话 / 先出结果
- 告诉观众“为什么会这样”
- 分 2-3 个节拍逐步补信息
- 最后揭晓答案或做反转
- CTA

首屏机制：
- 先出结果，不先出原因
- 也可以用“等下你就明白了”这类 delayed payoff

节奏倾向：
- 中快

字幕策略：
- 章节式
- 适合小标题分段，例如“先看结果”“问题在这”“真正关键点”

证据密度：
- 中

推荐素材角色：
- `process`
- `store_environment`
- `product_detail`

模板倾向：
- 适合能清楚分段的模板
- 适合支持章节标题、分段字幕或多段视觉切换的模板

BGM 倾向：
- 轻 suspense / 逐步抬升

对成片的影响：
- 完播率和后段留存更容易做起来
- 观众更愿意把视频看完再下判断

### 3. 三拍递进法

一句话理解：
把信息拆成 3 个连续节拍，每一拍都比上一拍更有价值或更接近结论。

文案骨架：
- 这件事我只讲 3 点
- 第 1 点：建立认知
- 第 2 点：补充关键误区或证据
- 第 3 点：给决定性动作或结论
- CTA

首屏机制：
- 开头直接告诉用户“就 3 点”
- 给出可预期的完成感

节奏倾向：
- 中

字幕策略：
- 章节式 / 序号式
- `01 / 02 / 03` 很重要

证据密度：
- 中到强

推荐素材角色：
- `product_detail`
- `process`
- 按 3 个节拍分别配支持素材

模板倾向：
- 适合字幕稳定、排版清晰、有列表感的模板
- 如果模板支持多次标题切换，会更好

BGM 倾向：
- 稳定推进型

对成片的影响：
- 结构清楚、用户容易跟上
- 最适合做“信息整理”和“条理表达”

### 4. 现场证明法

一句话理解：
不先说服，先给观众看过程、动作或结果，让“证明”先于“结论”。

文案骨架：
- 我直接给你看
- 过程怎么发生
- 哪个细节最关键
- 结果说明了什么
- CTA

首屏机制：
- 第一秒最好不是脸，而是动作、细节或结果画面
- 口播应该服务于证明，而不是替代证明

节奏倾向：
- 中快

字幕策略：
- 普通到强高亮
- 重点标出“关键动作”“结果”“对比”

证据密度：
- 强

推荐素材角色：
- `process`
- `product_detail`
- `store_environment`

模板倾向：
- 适合支持证据穿插、画中画、操作过程插帧的模板
- 如果模板只能纯口播，这套结构表现会打折

BGM 倾向：
- 轻节奏，不抢过程声画

对成片的影响：
- 信任感会更强
- 更像“看见了事实”，而不是“听了一段话”

### 5. 痛点共振法

一句话理解：
先准确说出观众熟悉的不舒服，再带他走向解释和缓解。

文案骨架：
- 你是不是也遇到过这个情况
- 这件事为什么让人烦/累/卡住
- 真正卡住你的不是表面问题
- 先做这一步
- CTA

首屏机制：
- 第一秒不是输出观点，而是指出一个熟悉的困境

节奏倾向：
- 中慢

字幕策略：
- 普通字幕为主
- 少量关键词高亮

证据密度：
- 弱到中

推荐素材角色：
- `store_environment`
- 情绪环境型镜头
- 如果有真实案例可手动补，但不建议 AI 硬补案例

模板倾向：
- 适合人物露出较稳定、镜头不太躁的模板
- 不适合过度花哨的转场和重字幕模板

BGM 倾向：
- 情绪共鸣型

对成片的影响：
- 更容易建立信任
- 会削弱“叫卖感”，增强“懂你”的感觉

### 6. POV 带入法

一句话理解：
让观众不是“看你说”，而是“跟着你看 / 跟着你经历”。

文案骨架：
- 跟我看一个过程 / 视角
- 现在发生了什么
- 你应该注意哪里
- 结果或结论
- CTA

首屏机制：
- 第一秒直接进入 POV 或跟拍视角
- 少解释，多带着走

节奏倾向：
- 中

字幕策略：
- 极简或导航型字幕
- 只提示关键观察点

证据密度：
- 中

推荐素材角色：
- `process`
- `store_environment`

模板倾向：
- 适合画面占比大、文字不要太重的模板
- 如果支持画中画或局部放大，体验更好

BGM 倾向：
- 氛围型 / 轻节奏

对成片的影响：
- 代入感更强
- 更适合把“过程理解”变成“亲历体验”

### 7. 对话碰撞法

一句话理解：
通过两种声音的对撞，把观众心里的疑问先替他说出来，再一一破解。

文案骨架：
- 声音 A：常见质疑 / 误解 / 借口
- 声音 B：回应
- 再抛一个更深层质疑
- 再回应
- 落结论和 CTA

首屏机制：
- 开场就让两个立场撞上
- 第一秒最好就是一句反问或质疑

节奏倾向：
- 中快

字幕策略：
- 角色标签式
- 适合用 `你以为 / 真相是`、`有人会说 / 我的回答是`

证据密度：
- 中

推荐素材角色：
- `product_detail`
- `process`
- 辅助型 reaction 镜头

模板倾向：
- 适合切换感明确、字幕区清楚的模板
- 若有双栏、对话框感或强字幕模板，会更匹配

BGM 倾向：
- 节奏轻推即可

对成片的影响：
- 更适合处理用户疑虑
- 会让视频更像“有交锋感的对话”，而不是单向输出

### 8. 对比翻转法

一句话理解：
把“旧状态”和“新状态”、“错误做法”和“正确做法”并列，让变化一眼可见。

文案骨架：
- 以前大多数人怎么做
- 这样做为什么出问题
- 换成另一种方式后发生了什么
- 关键差别在哪里
- CTA

首屏机制：
- 第一秒最好出现 A/B 对比
- 可以是画面对比，也可以是短句对比

节奏倾向：
- 中快

字幕策略：
- 强高亮 / 对照式
- 适合“以前 / 现在”“错误 / 正确”“表面 / 真正”

证据密度：
- 强

推荐素材角色：
- `product_detail`
- `process`
- 若有真实 before/after，则优先手动上传

模板倾向：
- 适合能做分屏、切换或明显前后状态变化的模板
- 如果模板空间太单一，这套结构会弱很多

BGM 倾向：
- 变化感明显的节奏

对成片的影响：
- 变化感更直接
- 转化意图通常更强，因为“差别”本身就是卖点

### 9. 回环重播法

一句话理解：
让视频结尾重新扣回开头，形成视觉或语义上的闭环，促进重复观看。

文案骨架：
- 开头先抛一个片段或一句半截话
- 中间补充过程和解释
- 结尾把最后一句或最后一镜接回开头

首屏机制：
- 开头必须是一个可回收的动作、句子或画面

节奏倾向：
- 中

字幕策略：
- 极简
- 不要太多解释，重在节奏闭环

证据密度：
- 中

推荐素材角色：
- `process`
- 1 个强记忆点画面

模板倾向：
- 适合镜头切换流畅、首尾接续感好的模板
- 不依赖复杂字幕，更依赖镜头设计

BGM 倾向：
- 有循环感、节拍感的音乐更合适

对成片的影响：
- 更容易形成重播
- 强在“观看体验完整”，不是强在信息密度

### 10. 视觉机关法

一句话理解：
让视觉变化本身成为核心内容，比如物体变形、空间错位、卡点替换、定格/停格、实拍小机关。

文案骨架：
- 文案尽量短
- 只保留引导理解的最少信息
- 让画面承担主要表达

首屏机制：
- 第一秒必须有“这怎么做到的”感觉

节奏倾向：
- 快

字幕策略：
- 极简或无字幕
- 只保留 1-2 个关键提示词

证据密度：
- 弱到中

推荐素材角色：
- `product_detail`
- 单个核心物体 / 核心动作

模板倾向：
- 适合画面空间大、字幕压制少的模板
- 不适合文字挤满画面的模板

BGM 倾向：
- 卡点型 / 强节奏型

对成片的影响：
- 更有“记忆点”和“分享感”
- 适合做品牌记忆、视觉惊喜、轻叙事表达

## 这 10 套结构如何进入产品

这 10 套结构不应该只作为“脚本文案分类”，而应成为上游意图层。它们至少应该影响 4 件事：

1. 脚本生成
   - 约束开场方式、节拍数量、转折位置、CTA 类型
2. 模板推荐
   - 不做大面积硬过滤，而是做推荐排序和弱匹配提示
3. 包装参数预设
   - 影响字幕强度、标题栏倾向、证据插入倾向、人物/画面比例倾向
4. 素材建议
   - 影响 Pexels 的查询策略和用户手动补素材的提示项

## 当前版本对系统最现实的影响

考虑到当前系统限制：

- 还没有 BGM API，所以 BGM 只能给建议，不能自动控制
- 已接入 Pexels 图片/视频，所以 AI 自动补素材可以真实发挥作用
- 闪剪模板池还不多，所以结构不能过度硬限制模板选择

因此现阶段最合理的落地方式是：

- 结构先影响模板推荐排序
- 结构先影响 `packRules / processRules` 预设
- 结构先影响 Pexels 素材角色与搜索词
- 结构先影响素材位数量和素材类型建议

而不是：

- 用结构把模板大面积禁掉
- 假装结构能直接控制外部剪辑引擎
- 假装系统已经具备智能 BGM 能力

## 下一步建议

如果要继续产品化，这份结构手册后面应继续拆成两层：

1. `StructureBlueprint`
   - 面向脚本生成
2. `PackagingIntent`
   - 面向模板推荐、参数预设、Pexels 素材建议

这样结构才能既不行业化，也不空心化。
