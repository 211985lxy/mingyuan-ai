# AIM 提示词清单 —— 内置块与触发规则（谁在什么时候生效）

> 更新：2026-09-02 · 分支 `feat/aim-user-instruction-single-source`
> 原则：**用户说了什么就照什么写；用户没说的不猜、不默认、不设卡。**
> 本文回答一个问题：生成一篇内容时，系统到底往提示词里放了哪些东西、谁触发的。

---

## 一、总览：三层架构（对标 Claude/ZCode 的分层）

| 层 | 什么时候生效 | 入口数量 | 状态 |
|---|---|---|---|
| ① 固定身份层 | 永远生效（人设 + 红线） | **3 套并存**（见 2.1） | ⚠️ 待统一 |
| ② 按需上下文层 | 用户给了/选了/确认了才带 | 各 1 个入口 | ✅ 已收敛 |
| ③ 显式技能层 | 用户点名才加载 | 1 个入口（信号驱动） | ✅ 已收敛 |
| ④ 隐性触发层 | **正则关键词命中就悄悄挂上** | 4 个开关 | ⚠️ 待显性化 |
| ⑤ 重试层 | 只有生成失败时注入 | 按失败类型 | ✅ 已清掉字数 |

## 二、逐层明细

### 2.1 固定身份层（人设 + 红线）

| 人设 | 用在哪 | 代码位置 |
|---|---|---|
| 「企业营销内容专家，直接完成用户本轮要求」+ 当前用户原话最高真源 + 输出标记规则 | **统一入口**（创作台主生成，content_producer） | `src/lib/aim/unified-content-prompts.ts` |
| 「企业营销内容专家（内容创作官）」+ 北极星目标 | **旧 generate 入口**（质检修订/渠道/编辑室/内容包） | `src/lib/aim-agent-content-producer.ts:97` |
| 「身经百战的太极营销创意总监」 | **聊天**（/api/aim/chat） | `src/lib/aim-agent-prompts.ts:192` |
| 各专家的 intro / placeholder / defaultInstruction（含「好的老板」开场口癖） | 界面引导与聊天人设补强 | `src/lib/aim-agent-guides.ts` |

**红线（所有路径共享，永远生效）**：无来源案例/数字禁令（防虚构）、对标防抄袭（≥30% 可感知重写、不连续沿用 12 字）、禁用词表（赋能/闭环/抓手…）、CoT 泄漏清洗。
**位置**：`aim-agent-prompts.ts`（BENCHMARK_REWRITE_GUARDRAIL / BUZZWORD_BAN）、`aim-generation-guardrails.ts`、`aim-generation-text.ts`。

### 2.2 按需上下文层（素材）

| 块 | 触发条件 | 代码位置 |
|---|---|---|
| 来源信封：用户原话 > 最近 12 轮对话 > 当前作品 > 参考材料 | 每次请求统一携带，优先级固定 | `src/lib/aim/content-source-envelope.ts` |
| 格式规范 FORMAT_INSTRUCTIONS（口播/公众号/朋友圈/社群/交接单/原始文案/小红书） | 按本次要求的格式带对应几段；**只含平台表达规范，无字数/数量/CTA 硬门槛**（2026-09 清理） | `src/lib/aim-agent-prompts.ts` |
| 知识库检索 | 任务已确认需要项目事实时（策略分档 light_edit/hot_topic/rewrite/deep/persona/conversion） | `aim-harness/context/load-generation-blocks.ts` |
| IP Wiki / 项目事实底盘 | **仅**用户点名"结合项目/知识库资料"，或任务确认需要且非轻改；轻改默认不注入 | `resolveIpWikiLoadFlag()`（同上文件） |
| 场景块（IP知识/本地商家/投流转化/小红书种草/KOL探店…） | 用户在界面**主动选择**场景才带 | `src/lib/content-scenario-config.ts` |
| 已确认母内容 canonical | 用户确认过母内容才带（派生不改事实） | `aim-agent-content-producer.ts` |
| 内容包平台契约 | 用户要求多格式内容包才带 | `src/lib/content-package-spec.ts` |

### 2.3 显式技能层（用户点名才加载）

| 块 | 触发条件 | 代码位置 |
|---|---|---|
| 方法论结构卡片（含"必须执行其结构与禁忌"前言） | **仅用户点了方法论/爆款技能**（activeMethodologySignals）；默认零注入 | `resolve-methodology-injection.ts` + `compose-matched-methodology-block.ts` |
| 用户自选方法论 profile | 界面选了才带（最多 1 个） | methodologyProfileIds |
| 爆款工具箱（开头库/结构库/结尾库） | 点了对应技能才注入 | progressive-prompt-flags（includeViralToolkit） |

### 2.4 隐性触发层（⚠️ 最"乱"的一块：正则命中即挂，用户不可见）

| 块 | 触发正则/条件 | 代码位置 |
|---|---|---|
| 发布包规则 | 输入含 发布包/发布文案/发布话题/话题标签… | `progressive-prompt-flags.ts` PUBLISH_PACKAGE_PATTERN |
| 对标防抄袭附加 | 输入含 对标/仿写/改写/复刻，或改写类任务 | 同上 includeBenchmark |
| 高风险"验证结果"规则（验证结论只进思考依据不进正文） | 正式交付类任务 | 同上 includeHighRisk |
| 爆款工具箱 | 输入含 开头优化/爆款结构/前3秒… | 同上 VIRAL_TOOLKIT_PATTERN |

### 2.5 重试层（失败才注入；已无任何字数目标）

完整性重试（截断/半句话）· CoT 泄漏重试 · 防虚构数字重试 · 对标相似度重试 · 统一入口协议重试（附确切格式标记清单）。
**位置**：`aim-generation-prompts.ts` 重试循环。

### 2.6 内部溯源（不进正文）

METHOD_NOTE 思考依据（10 节，含"八字与紫微"命理小节——无资料时写"未提供/待补充"）：只在折叠区展示，正文/复制/字数均不含。**位置**：`aim-content-creation-trace.ts`。

## 三、组装顺序

**统一入口（创作台主生成，content_producer）**：
`/api/aim/execute` → 语义理解（≤3 问，篇幅永不问）→ 确定性意图/缺口 → 生成：统一人设 + 信封素材 + 格式规范 + （技能/场景/项目资料按需）→ 完整性/防泄漏/防抄袭校验 → 交付（正文与思考依据分离）。

**旧 generate 入口（质检修订、渠道、编辑室、内容包、外部 agent API）**：
`/api/aim/generate` → 旧人设 + 工作流上下文 + 同样的按需块 → 同一套校验。**与统一入口的差异**：人设措辞不同、意图走正则 runtimeTask、无语义追问。

**聊天**：`/api/aim/chat` → 太极总监人设 + 对话 + 知识块 + 2.4 隐性触发块。

## 四、已清理存档（2026-09，防回归清单见 `aim-no-hidden-defaults-guard.test.ts`）

字数/时长一切强制口径（默认 2 分钟/400-500 字/95%-105% 对标长度/300 字场景上限/超长静默删句）· 公众号 2000 字下限 · 朋友圈/社群固定字数与强制互动 · 批量默认 3 条 · 仿写默认双版本 · 开头固定 10 条 · 发布话题固定 6 个 · 排产表固定 12 条 · 方法论默认获客 · IP Wiki 无条件加载 · "验证结果"进正文 · 伪节奏公式（每10-12秒40字/每2-4秒视觉点/前15秒）· "文盲式修改" · 朋友圈/社群三段式强制 · "每论点必须带案例"（与防虚构冲突）。

## 六、对标参考（Cyber Vibes 使用手册，2026-09-02 采纳）

对标结论：对方是"13 个专职智能体"，我们是"1 个创作官 + 场景体系"——架构路线不同，但对方有 4 个经过市场验证的产品模式值得吸收。

**本次已采纳（提交见 guides 修正）：**
- 六段式标准输入模板（我是谁/产品服务/目标客户/核心卖点≤3/内容目标可不填/篇幅可不填）——与我们"字数只随用户"的口径天然一致：不填就自然收束，改写/仿写参考原文篇幅；
- 常用追问清单：快捷提示新增 3 条迭代短语（改得更像真人口播 / 换开头 / 再来 3 版不同角度）；
- 长资料分批协议：用户分批发资料时逐批只回「收到」，说明发完再处理。

**已经对齐、无需改动的：**
- 关键信息缺口追问（对方的"信息缺口与补采建议"≈ 我们的编号追问，且我们≤3 问、篇幅永不问）；
- 智能体边界（实体获客 vs IP 问答 ≈ 我们的内容目的三分 + 场景体系）；
- 字数可不填、不填按原文篇幅（对方仿写默认 ≈ 我们的素材层体量语义）。

**待产品决策（暂不动，需要明确立项再做）：**
1. 口播结构呈现方式选项（对方 A 独白流 / B 结论先行 / C 对话记录，默认 C 可切换）——我们目前靠自然追问实现，要不要做成显式 A/B/C 切换；
2. 「IP 档案 / 爆款方法论」双资产链——**2026-09-02 勘察结论：架构已存在，缺的是入口**。
   已有：IP Wiki 本身就是"AOT 编译的定位底盘"（ip-wiki/context.ts，明确设计为替代 JIT 向量检索），
   核心页型与竞品七字段几乎一一对应（定位主张=我是谁 / 人设=独特人设经历 / 目标人群=服务谁+痛点 /
   成交路径=卖什么怎么转化 / 内容策略底盘+选题方向 / **爆款方法论已是独立页型**）；
   输入模板已补齐第 7 栏"独特人设"。
   缺口（按优先级）：
   a. 用户填写入口——七栏引导表单+行业输入示例（竞品真正的优势在这里，不在架构）；
   b. 完整度反馈——核心页缺失时给用户"补采建议"（compliance 只在生成侧校验，用户看不见）；
   c. 创作台组合语义——"带上 IP 档案 + 爆款方法论一起写"的显式开关与展示；
   d. 沉淀回路——对标拆解结果一键存为爆款方法论页（页型已支持，缺写入入口）；
3. 50 种人物风格洗稿库（鲁迅式/王小波式…）——内容资产建设，非架构问题；
4. 专职智能体拆分（账号拆解 / 前采整理 / 信息流话术 / 探店 / 短剧剧本）——走场景体系扩展还是独立智能体，取决于定位取舍。
