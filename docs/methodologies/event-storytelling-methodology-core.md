# 事件内容化 · 通用方法论

> **把任意一次项目现场 / 业务事件，提炼成 C 端、B 端都听得懂的内容故事**
> 一套与行业无关的"现场 → 内容"转化系统
>
> **适用场景**：视频日记、项目现场记录、出差 vlog、事件复盘叙事、客户案例纪实

---

## 核心心法（三条铁律）

**铁律一：现场是内容资产，不是流水账。** 一次事件可以沉淀 4 类资产：
- 🎯 **观点**（对行业的判断 → 建立专业权威）
- 📖 **故事**（有感染力的情节 → 引发情感共鸣）
- 💡 **选题**（未来创作方向 → 充实内容日历）
- 💬 **成交话术**（打动客户的语言 → 直接服务销售）

**铁律二：记录 ≠ 提炼。**
- ❌ "我们去了哪里、看了什么、见了谁。"
- ✅ "这件事**说明了什么**？**对谁有价值**？**能解决什么问题**？"

**铁律三：事件不是重点，矛盾才是重点。** 内容的"钩子"永远不是"发生了什么"，而是"这件事背后揭示了什么冲突"。

---

## 通用转化公式

```
真实事件  →  关键矛盾  →  核心观点  →  用户价值  →  内容表达
```

| 环节 | 关键动作 | 判断标准 |
|------|---------|---------|
| ① 真实事件 | 还原客观事实 | 不编造、不虚构 |
| ② 关键矛盾 | 找到冲突点 | 有利益分歧或价值对立 |
| ③ 核心观点 | 提炼鲜明见解 | 独特、可被记住 |
| ④ 用户价值 | 落到收益 | 情绪价值 或 认知增量 |
| ⑤ 内容表达 | 选对形式 | 视频 / 图文 / 直播 |

## 五步法（创作时严格按此流程执行）

### 第一步：找到事件里的矛盾 ⭐最关键

同一个事件，不同角色的"痛"完全不同。先把所有利益相关方列出来，再分别找他们的矛盾。

**受众分层三视角（通用填空）**：

| 视角 | 定义 | 关键矛盾公式 | 万能提问 |
|------|------|------------|---------|
| **终端使用者**（C 端） | 最终用产品/服务的人 | "我花了钱，却没得到该有的体验" | 体验焦虑、性价比、被欺骗感 |
| **中间合作方**（B 端） | 渠道 / 经销商 / 集成商 | "这事能不能复制、能不能赚钱" | 可复制性、利润空间、长期经营 |
| **决策方 / 采购方**（甲方） | 政府 / 大企业 / 管理层 | "出了问题谁担责、成本怎么控" | 风险、合规、管理效率、可监管 |

> 💡 把你的行业三类人填进去，矛盾自然浮现。

**矛盾挖掘四问（每次现场必答）**：
1. 谁在这件事里**最焦虑**？焦虑什么？
2. 谁的**利益**和谁的利益**冲突**了？
3. 表面上是一个问题，背后**真正的分歧**是什么？
4. 如果不解决，谁会**吃亏**？怎么吃亏？

### 第二步：锁定一个受众，对症下药

每个受众只关心"跟他有关的那一层"。一段内容如果同时想打动三类人，通常谁也打动不了。**先锁定一个受众，再开口。**

| 受众 | 关注维度 | 万能提问模板 |
|------|---------|------------|
| 终端使用者 | **看结果** | 我得到的东西，配不配我花的钱/时间？ |
| 中间合作方 | **看模式** | 能不能复制？能不能赚钱？能不能长期干？ |
| 决策方 | **看治理** | 能不能降风险、降成本？能不能被监管、被汇报？ |

### 第三步：把专业语言翻译成"人话"

**万能翻译公式**：`[技术/功能描述] → [解决了客户的什么痛点] + [带来了什么具体结果]`

- ❌ 不要说："我们用了 XX 技术实现 XX 功能"
- ✅ 换成说："这个帮您解决了 XX 问题，让您的生活/工作变好了 XX"

**自检标准**：如果一个完全不懂你行业的人，听完这句话能**复述**给朋友听，就算翻译成功。

### 第四步：提炼"可传播观点"（金句）

把整件事浓缩成 1～3 句话，要求**简单、直接、能被转述**。

**金句生成公式（4 种结构，任选）**：

| 公式 | 结构 | 示例模板 |
|------|------|---------|
| **否定 + 肯定** | "X 好不好，不是看 A，而是看 B" | "好不好，不是看 ___，而是看 ___" |
| **身份 + 转型** | "未来做 X 的人，不能只卖 A，要卖 B" | "未来 ___ 不能只 ___，而要 ___" |
| **重新定义** | "X 不是 A，而是 B" | "___ 不是炫技，而是 ___" |
| **反常识** | "大家以为 A，其实 B" | "都以为 ___，真正的问题是 ___" |

> 🎯 好观点的标准：① 一句话能说完 ② 有立场（不是"既要又要"）③ 听完想点头或想反驳。

### 第五步：按 5 段式通用模板形成故事结构

| 段落 | 作用 | 写什么 | 万能句式 | 建议占比 |
|------|------|--------|---------|---------|
| **01 发生了什么** | 事件 | 客观陈述关键事实，还原场景 | "上次我们去 ___，看到 ___" | 20% |
| **02 出现了什么问题** | 矛盾 | 点明核心冲突 / 痛点 | "但真实的麻烦是 ___" | 20% |
| **03 我们看到了什么** | 洞察 | 现象背后的逻辑 | "这其实说明 ___" | 25% |
| **04 得出了什么观点** | 结论 | 明确的判断 / 主张 | "所以我们的看法是 ___" | 20% |
| **05 对你有什么价值** | 利益 | 落到读者的收益 | "这意味着你可以 ___" | 15% |

> ⚠️ 多数人栽在前两段写太长（变成流水账），后三段太短（没有观点和价值）。严格按比例分配。

## 选题生成公式（一次事件 = N 个选题）

```
受众视角 × 内容角度 = 选题
```

| 内容角度 \ 受众 | 终端使用者 | 中间合作方 | 决策方 |
|---------------|----------|----------|-------|
| **痛点揭秘** | 用户为什么不__？ | 渠道为什么越来越难做？ | 监管为什么越来越严？ |
| **价值主张** | 怎样才算"值"？ | 未来靠什么赚钱？ | 怎样才算"管得好"？ |
| **方案对比** | 传统 vs 新做法 | 卖产品 vs 卖方案 | 被动补救 vs 主动治理 |

> 📊 一次扎实的现场考察，至少能从矩阵里拆出 **8～12 个选题**。

**选题自检三问**：
1. 这是个**真问题**，还是我自嗨？
2. 我的**目标受众**是谁？（只能选一个）
3. 我的**独特观点**是什么？（别人没说过的）

## 内容产出模板（填空即用）

```markdown
【标题】______？（用一个反常识 / 痛点提问）

1. 发生了什么（事件）
上次我们在 ______ 项目，看到 ______。

2. 出现了什么问题（矛盾）
但真正让人头疼的是 ______，而 ______ 又 ______。

3. 我们看到了什么（洞察）
这背后其实是 ______。

4. 得出的观点（结论）
所以，______ 不是 ______，而是 ______。

5. 对你意味着什么（价值）
如果你是 ______，这意味着你可以 ______。
```

## 与 IP 操盘方法论的关系

- 本方法论是 IP 操盘方法论的**场景化补充**，专门用于「有现场/事件素材」的创作。
- 当用户输入涉及项目现场、出差记录、客户案例、事件复盘时，应优先按本方法论的结构组织内容（事件→矛盾→洞察→观点→价值），而非按通用的口播/转化结构。
- 与 IP 操盘方法论中的「人设信任型」选题方向互补——本方法论提供的是具体的执行框架，IP 方法论提供的是风格和语气控制。
