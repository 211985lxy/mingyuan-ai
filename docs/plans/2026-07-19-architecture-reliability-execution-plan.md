## 已交付的工作包

### 耐久后台任务

- **允许范围**：`BackgroundTask` 模型、竞争分析和灵感处理的入队/领取/重试链路。
- **禁止范围**：不恢复退役视频/数字人能力，不调用真实模型，不修改生产配置。
- **验收**：原子领取、完成和租约恢复已在 Docker 隔离测试库验证。

### 迁移完整性门禁

- **允许范围**：基线顺序、已提交迁移目录和退役字段的离线检查。
- **禁止范围**：不执行 `db push`、`migrate resolve`、手工 DDL 或反向迁移。
- **验收**：`schema:migration-integrity` 与三条针对性单测通过。

### LLM 执行参数

- **允许范围**：客户端对 provider 尝试次数和输出 token 上限的整数归一化。
- **禁止范围**：不调整模型优先级、供应商密钥、价格或业务额度。
- **验收**：非法环境变量和非法请求参数都回退到安全上限，既有降级测试通过。

### 健康检查信息边界

- **允许范围**：公开健康端点的错误信息脱敏与服务端日志。
- **禁止范围**：不改变数据库/Redis 探针、发布事实或鉴权配置。
- **验收**：匿名响应只含 `unavailable`，内部错误仅进入日志。

## 合并与发布顺序

1. 先由审查者逐项审查 `main..chore/integrate-durable-background-tasks` 的七个提交；不使用整分支历史合并。
2. 在干净的 `main` 上移植获准提交，运行 `pnpm release:context`。
3. 完成 RP-01A/B/C 后重新运行本地发布门禁；未解决 Lint 前不得给出发布通过结论。
4. RP-02 只在备份和恢复边界明确后进行；差异脚本不是可执行迁移方案。
5. 最后在灰度环境执行 RP-04，并以明确 SHA、迁移状态和回滚点作为发布记录。

## 暂缓或拒绝

- 暂缓依据当前 `migrate diff` 直接生成“修复漂移”迁移：该脚本会重复添加已存在的外键。
- 暂缓全仓目录重构：现有领域边界门禁已通过，缺少可证明的业务收益。
- 暂缓真实模型全量 E2E：它会产生外部调用成本，应在 RP-04 的灰度预算内执行。
- 拒绝在共享 `main` 工作树中用 `reset --hard`、整分支合并或未记录备份的数据库操作。
