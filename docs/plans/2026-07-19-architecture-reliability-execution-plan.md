# 架构可靠性执行路线图

## 当前基线

- 候选分支仍为 `main`；`chore/integrate-durable-background-tasks-v2` 是基于最新候选重建的待审查输入，禁止整分支替代候选。
- 已验证输入提交：`59ab7e9`、`100b592`、`10ed0c3`、`32fdce2`、`2f17c19`、`4b16390`、`8d0ffdf`、`0099f11`。
- 已通过：`pnpm release:verify` 全量门禁，包括 Prisma 校验与生成、应用/测试类型检查、API 契约、领域边界、查询边界、架构尺寸、单元测试（1433）、Harness（125）、生产构建和隔离数据库 E2E（168）。
- 隔离库基线改由 MySQL 多语句连接执行，避免 Prisma CLI 将整份基线脚本作为单条语句而产生“迁移已标记、表未创建”的假阳性。
- 默认 E2E 已屏蔽所有模型供应商密钥；真实模型脚本质量检查独立为 `test:e2e:real-llm`，只能在获批预算的灰度阶段运行。
- 后台任务 Cron 每次只领取一个任务，路由上限为 300 秒、租约为 6 分钟；Kubernetes 清单已声明每 5 分钟触发一次。集群侧 `kubectl` dry-run 与真实灰度仍待具备集群访问权限后完成。
- 生产环境的 `BACKGROUND_TASKS_ENABLED` 默认关闭；只有 Kubernetes Web 清单显式启用。未配置等价调度器的部署会在入队前返回 503，避免生成永久排队任务。
- 生产迁移账本显示早期退役修复已完成但 `User.authVideoUrl` 仍实际存在；已在备份和零非空记录取证后追加幂等修复迁移，禁止用未记账手工 DDL 处理。
- 最新 `main` 的后续 UI 提交已消除旧 React Lint 阻断；当前集成分支的独立 Lint 已通过。
- `prisma migrate diff` 在 MariaDB 测试库报告降序索引和外键重建差异，但 Prisma 反射与迁移记录均证明关键表存在；不得把该 SQL 当作修复迁移执行。

## 已交付的工作包

### 耐久后台任务

- **允许范围**：`BackgroundTask` 模型、竞争分析和灵感处理的入队/领取/重试链路。
- **禁止范围**：不恢复退役视频/数字人能力，不调用真实模型，不修改生产配置。
- **验收**：原子领取、完成和租约恢复已在 Docker 隔离测试库验证。

### 迁移完整性门禁

- **允许范围**：基线顺序、已提交迁移目录和退役字段的离线检查。
- **禁止范围**：不执行 `db push`、`migrate resolve`、手工 DDL 或反向迁移。
- **验收**：`schema:migration-integrity` 与三条针对性单测通过。

### LLM 执行参数

- **允许范围**：客户端对 provider 尝试次数和输出 token 上限的整数归一化。
- **禁止范围**：不调整模型优先级、供应商密钥、价格或业务额度。
- **验收**：非法环境变量和非法请求参数都回退到安全上限，既有降级测试通过。

### 健康检查信息边界

- **允许范围**：公开健康端点的错误信息脱敏与服务端日志。
- **禁止范围**：不改变数据库/Redis 探针、发布事实或鉴权配置。
- **验收**：匿名响应只含 `unavailable`，内部错误仅进入日志。

### 发布验证可重复性

- **允许范围**：隔离测试库建库/基线执行、默认 E2E 的密钥隔离、真实模型 E2E 的独立入口和发布验证顺序。
- **禁止范围**：不读取或输出生产数据库凭据，不运行真实模型调用，不修改生产环境。
- **验收**：`pnpm release:verify` 已通过；数据库迁移状态在 E2E 清理测试库前验证，生产构建固定使用 `NODE_ENV=production`。

### 后台任务调度接线

- **允许范围**：后台任务 Cron 的批次、执行/租约时限、Kubernetes CronJob、运行清单和路由契约测试。
- **禁止范围**：不执行真实模型任务，不变更部署密钥或生产集群，不在无调度器的目标环境启用任务生产入口。
- **验收**：路由认证与单任务批次单测通过、应用类型检查通过、Kubernetes 清单待集群侧 dry-run 和最小任务灰度验证。

## 合并与发布顺序

1. 先由审查者逐项审查 `main..chore/integrate-durable-background-tasks-v2` 的获准提交；不使用整分支历史合并。
2. 在干净的 `main` 上移植获准提交，运行 `pnpm release:context`。
3. 每次移植后重新运行本地发布门禁；Lint 已通过但不能作为未来提交的豁免。
4. RP-02 只在备份和恢复边界明确后进行；差异脚本不是可执行迁移方案。
5. 最后在灰度环境执行 RP-04，并以明确 SHA、迁移状态和回滚点作为发布记录。

## 暂缓或拒绝

- 暂缓依据当前 `migrate diff` 直接生成“修复漂移”迁移：该脚本会重复添加已存在的外键。
- 暂缓全仓目录重构：现有领域边界门禁已通过，缺少可证明的业务收益。
- 暂缓真实模型全量 E2E：它会产生外部调用成本，应在 RP-04 的灰度预算内执行。
- 拒绝在共享 `main` 工作树中用 `reset --hard`、整分支合并或未记录备份的数据库操作。
