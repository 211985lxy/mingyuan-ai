# 仓库收敛与业务线整合计划

## 目标

以 `chore/release-convergence` 为唯一候选分支，在不回退 90 天升级能力的前提下，逐步吸收 PR #17 中已验证的创作、编辑与视频能力。

## 已确认事实

- 候选分支基于当前 `main`，且已通过 `pnpm release:context`。
- PR #17 与候选分支有 23 个核心冲突；禁止整包自动合并。
- PR #17 的客户端/服务端导入边界问题已在其分支修复（`a9ad76e`），生产构建通过。
- 视频号提取服务商尚未确定；只能保留可配置边界，不能宣称上线可用。

## 执行顺序

1. 建立候选分支可重复的依赖、类型、测试和构建基线。
2. 整合统一创作台与内容版本管理：先数据模型与 API，再编辑器入口；每次提交后验证类型、相关单测和构建。
3. 整合公众号预览、小红书评测与图文画布；只在创作台入口可达后引入，避免死功能。
4. 整合 Token 成本观测与模型路由：保留当前 90 天升级运行时，吸收独立计量能力；真实价格和模型可用性以环境配置与实测为准。
5. 整合视频流水线：先抖音/飞书已知链路；视频号 Provider 仅在取得服务商契约和真实样本后启用。
6. 逐项归档已完成的 Z Code 计划与 Kimi 交接材料；未实现计划保留为待办，不伪装成已交付。

## 验收门槛

- 每个整合包独立提交，候选分支无未提交改动。
- `pnpm --dir apps/web typecheck`、相关单测与 `pnpm --dir apps/web build` 通过。
- Prisma 改动必须核对迁移顺序与现有数据库状态。
- 涉及飞书、模型或第三方提取服务的能力必须标明真实联调状态。
