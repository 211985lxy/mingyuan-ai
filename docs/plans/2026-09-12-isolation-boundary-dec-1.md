# DEC-1 隔离边界：维持项目级，不改成账号级

> 状态：书面结论 · 日期：2026-09-12 · 截止：批次 2 末
> 上游：《明动AIM-竞品借鉴增量升级计划-2026-09-12》DEC-1
> 判断依据：WP-2.1 客户构成指标。指标不全时，**默认拒绝**「改成账号隔离」。

## 一句话结论

付费主语仍是「机构服务多客户」，不是「一个人玩多号矩阵」。隔离边界继续是**项目**。账号历史挂在项目下。任何「改成账号隔离」的开发默认拒绝，直到 WP-2.1 拿出相反的真实构成。

## 问了什么

竞品把每个账号的定位/数据/项目/素材四维切开，叙事是个人或多号工作室。AIM 现有口径写在 `row-ownership.ts`：一个登录账号绑定一个 IP 项目，同项目可以多人协作，所以项目才是正确边界。

## 用了什么依据

- 代码事实：项目是隔离主键；A1 的 `AccountWorkAsset` 已强制带 `projectId`。
- WP-2.1 指标层：本 worktree **没有**可引用的完整客户构成报表（机构客 vs 矩阵玩家占比、每客账号数分布）。缺数据不等于可以按竞品改架构。
- 闸门 4：改成账号隔离会伤「机构服务多客户 + 项目制交付」的差异化。

## 裁决

1. **维持项目隔离。**
2. A1 投影、A3 预测、A6 导出全部按当前绑定项目切，不按抖音号切一等实体。
3. 账号级素材没有项目字段的，导出时标明「账号级引用」，不假装已经项目隔离。
4. 复审条件：WP-2.1 连续两个经营周期证明「矩阵玩家付费占比稳定高于机构客」再开会，不能凭演示视频重开。

## 明确不收

- 把 `AccountWorkAsset` 改成账号一等、项目可空。
- 让同一登录号下的多个客户项目共享原始作品和逐字稿。
- L2 单机个人版（数据落在个人文件夹、没有组织记忆）。
