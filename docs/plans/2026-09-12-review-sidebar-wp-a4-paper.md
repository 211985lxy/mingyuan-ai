## 1. 要验证的体验

成稿出来后，右侧常驻一块「编导评审」，不要再跳到另一个质检页。建议按严重度编号，并按「改这一条值不值得」（ROI）排序。

AIM 里已经有打分和验收：`quality-gate.ts` 四维分、`semantic-delivery-verifier.ts` 交付验收、裁决卡。缺的是常驻位置和结构化呈现。

## 2. 纸面结构（给用户看的草图，不是设计终稿）

```
┌ 成稿区 ──────────────┬ 编导评审 ──────┐
│ 口播 / 标题 / 封面   │ ① 开头 8 秒没钩子   高 │
│                      │    改完预估多留 20% 完播 │
│                      │ ② 术语听众听不懂   中 │
│                      │    换成客户原话，成本低 │
│                      │ ③ 封面字太多       低 │
│                      │    可改可不改         │
└──────────────────────┴────────────────┘
底部：采纳 / 忽略 / 先问一句
```

规则（写在纸上问，不写进代码）：

- 严重度来自现有四维打分，不另造一套分。
- ROI = 「改动成本低 + 对完播/询盘影响大」靠前。
- 没有建议时写「这稿过关，没有必须改的」，不要空转一堆废话。
- 不自动改稿。点「采纳」才进现有润色/重写。

## 3. 5 人访谈问法

对象：正在用 AIM 出稿的运营或编导，不是内部开发。每人 15 分钟，拿纸面或 Figma 框，不点真实按钮。

1. 你现在改稿时，质检结果在哪看？找不到会怎样？
2. 这块侧栏出现在成稿旁边，是帮你加快，还是挡视线？
3. 「按值不值得排序」和「按严重度排序」，你先看哪个？
4. 空状态那句「这稿过关」你信吗？不信是因为什么？
5. 如果只能留一个能力：常驻侧栏，还是现在这种生成后弹一次的质检？为什么？

通过线：5 人里至少 4 人说「愿意每天用」且能指出哪条建议会真的改。不过线：归档，批次 3 不做开发。
