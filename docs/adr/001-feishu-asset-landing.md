# ADR-001: 飞书原生资产落地

- 状态: 已接受
- 日期: 2026-07-22
- 决策者: AIM 团队

## 背景

AIM 生成结果当前以数据库记录（AimGeneration）和纯文本回复形式存在，缺乏飞书侧的可协作资产。需要把执行结果落地为飞书 Doc/Base/Sheets/Drive 资产，支持人工审核、协作编辑和知识沉淀。

## 决策

### 真源划分

| 内容 | 真源 |
|---|---|
| 经营事项状态 | 飞书「AIM经营事项」五态状态机 |
| 模型输入/输出快照、Token、成本 | AIM 数据库（AimGeneration） |
| 最终可编辑文案、报告、方案 | 飞书 Doc |
| 内容日历、竞品记录、交付任务 | 飞书 Base |
| 分析矩阵、计算报表 | 飞书 Sheets |
| 图片、PDF、导出文件 | 飞书 Drive |
| 人工修改意见 | 飞书评论/审核记录 |
| 正式企业知识 | KnowledgeEntry（需人工批准） |

飞书不是 AIM 数据库的替代品，而是最终业务资产的协作正本。

### 失败语义

| 失败情况 | 处理 |
|---|---|
| 主要 Doc 创建失败 | 经营事项失败，人工接管 |
| 权限设置失败 | 不写结果链接，人工接管 |
| 创建成功但响应丢失 | 按稳定标记搜索并复用资产 |
| Base/Sheet 次要资产失败 | 主 Doc 存在时进入审核，标注缺失资产 |
| 回写经营事项失败 | 保留 Receipt，幂等重试回写 |
| 通知失败 | 记录错误，不回滚经营事项 |
| 文档回读不一致 | 停止推进，人工接管 |

### 版本策略

- 经营事项五态状态机不变。
- 不建设第二套 Agent 运行时。
- lark-cli 作为统一服务端飞书能力网关。
- Shortcut 优先，Shortcut 不覆盖时才调用原生资源命令。
- 模型不能生成或执行任意 CLI 命令。
- MVP 阶段 Receipt 写入 AimGeneration.taskSpec，暂不新增资产表。
- 功能开关 + Shadow Mode 灰度上线。

### 核心边界

- AIM 负责：执行、状态、审计、权限决策。
- 飞书负责：资产承载、协作编辑、评论审核。
- 禁止：对协作文档全文 overwrite、删除人工评论、自动接受客户修改、未经批准写入知识库。

## 后果

- 正面：生成结果变为可协作资产，支持人工审核和知识沉淀。
- 负面：增加飞书 API 依赖，需要处理网络失败和权限问题。
- 风险：飞书 API 限流、文档冲突。通过幂等键和版本保护缓解。
