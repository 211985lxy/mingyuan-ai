# AIM 用户指令分层与输出闸门设计

## 目标

修复内容创作台把“根据这些框架写 20 篇脚本”误判为“只改开头”，以及模型内部草稿被当成成稿展示的问题。修复应覆盖同类批量创作表达，不能只补一个固定关键词。

## 已确认根因

1. 当前意图规则在整段输入上扫描动作词和部位词，没有区分用户命令与粘贴素材。
2. 创建动作只覆盖“写一篇、写一条”等固定短语，不覆盖“写20篇、各写3条、批量出一组”。
3. 错误意图经用户确认后被冻结为唯一权威，后续生成器无法纠正。
4. 单格式响应缺少合法 `===FORMAT:...===` 标记时，解析器会把整段模型输出兜底为正文；内部复述和自我讨论因此可能直接展示。

## 设计

### 1. 命令与素材分层

新增一个纯函数提取“意图判定文本”。优先识别 `【待修改原文】`、`【原文】`、`【参考素材】`、`【脚本框架】`、`【素材】` 等明确素材边界；边界之前是用户命令，边界之后只作为生成素材。

没有明确边界时保持现有全文判定，避免改变普通短指令和纯原稿润色行为。该函数只服务意图与 runtimeTask 路由，不裁剪实际生成输入。

### 2. 数量化创作识别

创建动作识别支持：

- `写20篇/条/个/版`
- `各写3篇/条`
- `每种写5篇/条`
- `批量写/批量生成/批量出一组`
- `按这些框架写脚本`、`照这个框架出一组`

明确创建命令优先于素材中的局部部位词，并强制 `scope=full`。明确的“只改这20篇的开头”仍识别为 `local_edit/opening`。

### 3. 冻结前冲突校验

冻结结构化意图前复用同一命令文本：若命令具有强创建信号，而候选结果为 `local_edit`，必须重建为 `create/full`。这既保护本地规则，也保护可选的向量兜底，防止近义匹配覆盖显式命令。

不新增第二套意图系统，继续复用现有 `AimTurnIntent` 与 `actionToRuntimeTask`。

### 4. 输出交付闸门

单格式生成缺少合法 FORMAT 标记时，不再无条件把整段响应作为正文。仅当文本通过“可交付正文”检查时才允许兼容兜底；出现以下内部草稿特征则判定无正文：

- `内部复述`、`用户真实意图`、`本轮 runtimeTask`
- `等一下，我重新审视`、`最终决定`
- 连续的自我决策表述，如“我应该/我不应该/我要做的是”

生成循环将其视为不完整结果并自动重试；重试仍失败时返回现有可行动错误，不展示内部草稿。

该闸门只拦截高置信内部元话语，不根据普通“我”字句判断，避免误伤第一人称口播。

### 5. 思考依据边界

本修复不重构整个教学式溯源功能。合法 `AIM_METHOD_NOTE` 继续由现有逻辑折叠展示；未放入合法标记的逐步推理不得进入正文。后续若要彻底改为服务端确定性摘要，应作为独立工作包处理。

## 修改范围

允许修改：

- 意图文本提取与 `AimTurnIntent` / `runtimeTask` 判定
- 意图向量覆盖的硬边界
- 多格式响应解析和不完整结果判定
- 对应单元测试与 eval fixture

禁止修改：

- 数据库 Schema、生产部署配置、模型供应商路由
- 内容工作流 UI 布局
- 知识库检索、风格档案、方法论系统
- 主目录现有未跟踪文件

## 验收标准

1. 用户真实输入“把这几个框架写20篇脚本 + 待修改原文”判定为 `create/full`，运行时任务为 `new_copy`。
2. 素材中的“开头、钩子、结尾、CTA、待修改原文”不能覆盖明确创作命令。
3. “只改这20篇的开头”仍判定为 `local_edit/opening`。
4. “每种框架各写3条”“批量出一组脚本”等表达判定为 `create/full`。
5. 单格式响应只有内部复述且无 FORMAT 标记时不再作为正文交付。
6. 普通干净的单格式旧模型响应仍可兼容兜底，避免无关回归。
7. 相关意图、生成解析、内容生成测试通过；TypeScript 类型检查和架构体积门禁通过。

## 非目标

- 不保证一次请求能在模型输出上限内完成任意数量的超长脚本；数量与总长度容量规划另行处理。
- 不把全部意图判断迁移到 LLM，也不新增新的 Agent 或页面。
- 本工作包不部署生产环境；上线需在代码验证后按独立发布流程执行。
