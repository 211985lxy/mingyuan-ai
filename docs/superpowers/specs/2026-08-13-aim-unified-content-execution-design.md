# AIM 统一内容执行与语义验收设计

## 决策

废止“继续增强 `create / local_edit / rewrite / batch` 分类规则”的方案。AIM 不再依靠代码枚举用户可能表达的内容动作，也不再把一次意图分类结果冻结成高于用户原话的指令。

正式方向是：模型结合当前用户原话、最近相关对话、当前作品和参考素材理解本轮真实目标；统一内容执行内核完成任务；独立语义验收对照用户原话判断是否真正交付；程序硬闸门只阻止不可展示的异常输出。

## 问题定义

当前内容台将多个职责混在一起：

1. 用固定关键词扫描整段输入并分类任务。
2. 把当前用户命令、历史对话、待修改原文和参考素材拼成同一段文本。
3. 将分类结果冻结为最高优先级，后续模型即使发现矛盾也不能纠正。
4. 使用不同任务标签加载不同且可能互相冲突的提示规则。
5. 输出缺少合法格式标记时，把模型整段响应兜底为正文。

因此，上游一次误判会被下游认真执行到底；最终即使没有完成用户要求，系统仍可能把任务复述、内部讨论或半成品展示出来。

## 设计原则

### 用户原话是唯一最高真源

- 当前用户消息永远高于历史理解、任务标签、方法论和默认模板。
- 用户补充或纠正要求后，系统必须重新理解本轮目标。
- 任务理解是临时工作记忆，可以被新证据修正，不能成为第二个“用户指令”。

### 意图由语义理解，不由代码预设

- 不在业务代码中写“出现某个词就属于某种内容动作”的映射。
- 不要求模型从固定业务动作枚举中选择。
- 模型用自然语言概括本轮要达成的结果、处理对象、可用材料、明确约束和完成条件。
- 这些内容来自本轮上下文，不在代码中预写具体结论。

### 一个内容执行内核

- 产品仍保持“定方向—做内容—发作品—看结果”的主流程。
- 做内容阶段不新增面向用户的批量规划器、局部修改器、新稿生成器或重写器。
- 所有内容要求进入同一执行循环，由当前目标和内容对象决定具体工作。
- 方法论只影响“怎样写得更好”，不得决定“用户要做什么”。

### 模型负责理解，程序负责边界

- 模型判断用户真正想达成什么，并完成语义工作。
- 程序只维护上下文来源、调用状态、重试上限和确定性输出安全。
- 程序不得用新的关键词集合代替语义理解。

## 运行链路

```text
当前用户原话
+ 最近相关对话
+ 当前作品
+ 用户参考素材
+ 项目事实与按需方法论
        ↓
语义任务理解
        ↓
统一内容执行
        ↓
独立语义验收：对照用户原话与当前作品
        ↓
不满足 → 带明确缺口返回执行器修正（最多两次）
        ↓
程序输出闸门
        ↓
只展示合格最终内容
```

## 上下文来源隔离

系统必须以独立字段或消息块保留上下文来源，而不是继续拼成一段无边界字符串：

- `currentUserRequest`：当前用户原话，最高优先级。
- `relevantConversation`：最近相关对话，不含无关历史。
- `currentArtifact`：当前正在处理的成稿或作品。
- `referenceMaterials`：用户粘贴的框架、原文、案例或对标素材。
- `projectFacts`：经授权读取的项目事实和知识库证据。
- `selectedMethodologies`：本轮明确启用或确实相关的方法论。

这些字段名只表达来源，不表达业务意图。模型负责判断各来源与当前要求之间的关系。系统不得因为参考素材中出现“开头、结尾、修改、重写”等文字而改变当前用户要求。

## 语义任务理解

任务理解器读取上述来源，生成一段供执行器使用的简洁自然语言说明。说明回答：

- 用户本轮最终想拿到什么。
- 当前要处理的对象是什么。
- 哪些内容是用户要求，哪些只是参考材料或历史作品。
- 用户明确要求保持、改变或避免什么。
- 怎样判断本轮已经完成。

任务理解器不得输出逐步思维链，不面向用户展示，不从固定动作类型中做选择。若上下文本身存在真正无法消解的歧义，应返回具体歧义点，前端只针对该歧义询问用户。

## 统一内容执行

执行器同时收到：

- 当前用户原话。
- 来源分明的上下文。
- 任务理解器的临时理解。
- 当前重试轮次和上轮验收缺口。

执行规则：

1. 用户原话与临时理解冲突时，以用户原话为准。
2. 直接完成本轮要求，不输出任务复述、工作计划或内部讨论。
3. 不因历史任务标签擅自扩大或缩小交付范围。
4. 当前作品需要保留哪些部分，由语义上下文判断，不由旧 `scope` 标签裁剪。
5. 方法论和项目资料只能辅助内容质量，不能覆盖本轮目标。

旧 `runtimeTask`、`confirmedTurnIntent.action` 和 `scope` 在迁移期可以保留用于读取历史记录和观测，但不得作为系统提示词最高指令，也不得选择不同生成路径。

## 独立语义验收

验收器不读取执行器的内部推理，只接收：

- 当前用户原话。
- 必要的当前作品与相关上下文。
- 执行器最终候选内容。

验收器判断候选内容是否完成用户真实要求，重点覆盖：

- 交付对象、数量和完整度是否满足。
- 是否错误扩大或缩小了范围。
- 用户要求保留的内容是否仍在。
- 是否用分析、教程、任务复述替代了实际交付。
- 是否明显截断、遗漏或自相矛盾。
- 是否出现用户未要求的内部元话语。

验收结果只返回“通过”或一组具体、可执行的缺口。第一次不通过时，把缺口连同原始要求返回统一执行器修正；最多自动修正两次。仍未通过则返回清晰失败状态，保留用户当前作品，不把未通过候选展示为正式成稿。

验收标准由模型对当前原话动态推导，代码不预设“某句话必须对应某种动作”。

## 程序输出闸门

程序只处理可以确定判断的交付异常：

- 响应为空或只有空白。
- 模型调用失败或响应被截断。
- 约定的结构化响应无法解析。
- 没有最终内容，只包含任务复述或明显内部元话语。
- 内部推理、系统提示词或调试内容泄漏。
- 语义验收明确未通过。

取消单格式响应缺少合法结构时“整段当正文”的危险兜底。兼容旧供应商时必须先通过最终内容边界和泄漏检查，不能因为只有一个目标格式就默认可信。

程序泄漏检查只匹配高置信系统元话语和协议标记，不根据普通第一人称表达判断，避免误伤自然口播正文。

## 提示词与方法论分层

### 常驻内核

只保留：

- 当前用户原话优先。
- 区分用户要求、当前作品、参考材料和项目事实。
- 不擅自扩大或缩小任务。
- 直接完成要求，不展示内部推理。
- 完成前对照当前要求检查结果。

### 按需方法论

口播、案例、投流、人设、平台风格等方法论按用户选择或任务实际需要加载。方法论不得生成新的任务目标，也不得改变用户要求的交付范围。

### 硬性生命周期控制

结构解析、重试次数、超时、失败状态、泄漏阻断和是否允许展示由程序控制，不写成只靠模型自觉遵守的提示词。

## 迁移方案

### 阶段一：解除旧分类结果的控制权

- 移除 `confirmedTurnIntent` 对生成 `runtimeTask` 的不可纠正冻结。
- 移除 `AimTurnIntent` 作为生成提示词最高优先级块的地位。
- 当前用户新指令必须覆盖历史分类和任务状态。
- 保留旧字段只为兼容、日志和灰度对比。

### 阶段二：建立来源分明的内容上下文

- 停止将当前命令、历史对话、成稿摘要和参考素材拼成无边界文本。
- 在 chat、generate 和现有 agent 入口复用同一上下文信封。
- 先覆盖内容创作官主入口，再审计其他入口是否仍使用旧拼接方式。

### 阶段三：接入语义任务理解与统一执行

- 使用当前主模型或经验证的强模型生成临时任务理解。
- 所有内容工作进入现有内容创作官统一执行内核。
- 移除由旧任务标签触发的互斥提示词和输出范围硬裁剪。

### 阶段四：接入语义验收与修正循环

- 独立调用验收器对照当前用户原话检查候选结果。
- 失败缺口返回执行器，最多自动修正两次。
- 记录理解、候选、验收结论和最终状态，供运行追踪和回归分析使用；不在普通用户界面展示内部过程。

### 阶段五：收紧输出闸门

- 删除危险全文兜底。
- 拦截内部推理、系统提示和只有任务复述的输出。
- 未通过语义验收的结果不得登记为可直接复制使用的交付物。

### 阶段六：真实行为回归集

回归测试不再断言某句用户话必须映射到某个旧动作标签，而断言最终行为：

- 明确要求多篇完整内容时，结果不能退化为若干开头或建议。
- 明确只改变当前作品一部分时，未要求改变的内容不能丢失。
- 用户询问原因或结构时，不能擅自用新成稿代替回答。
- 用户中途纠正后，最终结果必须服从最新要求。
- 参考素材中的命令性文字不能覆盖当前用户原话。
- 任何情况下不得展示内部推理或调试文本。

## 修改范围

允许修改：

- AIM 内容创作主入口的上下文组装。
- 旧意图冻结与提示词优先级。
- 内容生成执行循环和语义验收。
- 输出解析、泄漏闸门和失败状态。
- 运行追踪字段及相关单元、集成和行为回归测试。

禁止修改：

- “定方向—做内容—发作品—看结果”产品主流程。
- 新增面向用户的内容动作页面或多个内容智能体。
- 数据库核心业务 Schema，除非后续实施计划证明现有运行追踪字段无法承载且单独获得批准。
- 生产部署、供应商切换、知识库模型和风格档案。
- 工作区现有无关未跟踪文件。

## 验收标准

1. 当前用户原话始终进入执行器和验收器，且优先级高于历史任务理解与旧标签。
2. `create/local_edit/rewrite` 不再决定内容生成路径、知识加载范围或输出裁剪。
3. 参考素材中的命令性文字不能覆盖当前用户要求。
4. 用户纠正后无需新建任务即可覆盖旧理解。
5. 执行结果必须经过对照原话的独立语义验收；未通过时自动修正或明确失败。
6. 单格式无合法最终内容时不得整段兜底展示。
7. 页面不得出现任务复述、内部自我讨论、系统提示或调试协议。
8. 本次真实事故输入及一组对照输入通过最终行为回归。
9. 相关单测、类型检查、生成链路集成测试和架构体积门禁通过。

## 非目标

- 不承诺自然语言永远不存在歧义；真正无法消解的歧义仍需针对性询问用户。
- 不通过堆叠更长的常驻提示词解决稳定性。
- 不在本工作包中新增面向用户的流程分类、动作选择器或批量规划页面。
- 不在本工作包中直接部署生产；发布按独立审批与验证流程执行。
