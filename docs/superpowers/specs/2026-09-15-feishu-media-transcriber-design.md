# 飞书“小D”音视频转录整理设计

## 1. 目标

在 AIM 现有飞书机器人中增加一条独立的“音视频转录整理”路径：用户在已绑定项目的飞书会话中发送明确的整理指令和一个公开视频链接，系统提取音视频文字，生成忠实、可读的“分享式提纯稿”，创建新的飞书文档，并在原消息线程返回文档链接。

这项能力服务于 IP 资产沉淀：把用户来不及观看的音视频转成可阅读、可检索、可后续确认入库的内容资产。它不是摘要器，也不是新的选题或文案生成入口。

## 2. 已验证事实与假设

### 已验证事实

- 飞书消息统一进入 `apps/web/src/app/api/integrations/feishu/events/route.ts`。
- 当前飞书视频链接会进入 `processVideo`，依次执行文案提取、总结、选题、竞品、文案灵感，并可写入飞书素材库。
- `processVideo({ skipAiProcessing: true })` 已支持只执行视频文字提取并返回 `extraction`。
- `createFeishuDoc` 和 `fetchFeishuDoc` 已提供飞书文档创建与回读能力，并统一通过 `lark-cli-runner` 执行。
- `replyFeishuTextMessage` 已支持对原消息进行带幂等键的线程回复。
- 视频号文字提取尚未完成真实供应商联调，当前必须明确失败，不能伪装支持。

### 产品假设

- 用户愿意通过“小D”“转录”“整理”或“提纯”等显式指令触发此能力。
- 第一阶段只处理一条消息中的第一个受支持视频链接。
- 第一阶段处理公开链接，不包含飞书音视频附件下载。
- 提纯稿创建成功后先作为项目相关外部资料交付，不自动写入正式知识库。

## 3. 范围

### 本工作包包含

- 显式小D指令识别与飞书事件分流。
- 复用现有视频文字提取链路。
- 新增分享式提纯服务和固定输出契约。
- 创建并回读飞书文档。
- 在原飞书消息线程回复接收状态、成功链接或可行动错误。
- 消息级幂等，避免飞书事件重放产生重复文档。
- 单元测试、相关集成测试和一个真实公开视频的飞书端到端验收。

### 本工作包不包含

- 生产部署或功能开关放量。
- 视频号未联调能力。
- 飞书音频、视频附件下载。
- 一次处理多个链接。
- 自动写入正式知识库、自动生成选题、竞品分析或新文案。
- 新建第二套 Agent 运行时或独立机器人应用。

## 4. 方案选择

采用“独立小D编排器，复用现有能力”。不把忠实整理继续堆进现有 5a–5e 内容生产流水线，也不部署独立 Hermes 服务。

理由：

- 保持“忠实提纯”和“内容再创作”的业务边界。
- 复用已经存在的视频提取、模型路由、飞书文档和消息回复能力。
- 不引入第二套身份、配置、监控和项目上下文。
- 变更可通过独立分流开关回退，不影响普通视频链接的原行为。

## 5. 用户交互

### 触发条件

消息必须同时满足：

1. 来自已绑定 AIM 项目的飞书会话。
2. 包含“小D”“转录”“整理”或“提纯”中的明确意图。
3. 包含一个现有链接检测器支持的视频链接。

示例：

- `小D，整理一下 https://...`
- `帮我转录并提纯这个视频：https://...`
- `整理 https://...`

只有链接、没有整理意图时，继续进入现有视频内容流水线。显式“收选题”仍优先进入灵感采集，不得被小D分流抢占。

### 即时回复

在 live 模式下，接受任务后立即在线程回复：

> 已收到，正在转录并整理为可读文稿。完成后我会把飞书文档发在这里。

`capture_only` 和 `evaluate` 模式继续遵守现有回群抑制纪律，不发送即时或完成回复。

### 完成回复

成功后回复：

- 素材标题。
- 来源平台。
- 完整提纯稿的飞书文档链接。
- 一句事实核对提醒。

不得把长篇正文直接刷进群聊。

## 6. 架构与组件

### 6.1 小D意图识别

新增纯函数识别器，输入原始消息文本，输出是否为小D整理意图。识别器只判断显式关键词，不调用模型，便于测试和避免路由漂移。

飞书事件路由顺序为：

1. 校验事件、签名和渠道绑定。
2. 判断显式“收选题”并保留其最高优先级。
3. 检测视频链接。
4. 若命中小D意图，进入小D编排器。
5. 若只有视频链接，进入现有完整视频流水线。
6. 其余消息保持原 AIM 对话或灵感采集行为。

### 6.2 小D编排器

新增单一职责服务，输入：

- `messageId`
- `chatId`
- `userId`
- `projectId`
- `videoUrl`
- `source`
- `executionMode`

输出采用可判别联合类型：

- `completed`：标题、平台、文档 token 和 URL。
- `failed`：稳定错误码和面向用户的错误信息。
- `duplicate`：复用已有结果，不创建第二份文档。

编排器步骤：

1. 通过消息 ID 获取或创建任务记录。
2. 调用现有视频提取能力，跳过 5b–5e。
3. 校验存在有效转录文本。
4. 调用分享式提纯服务。
5. 创建新的飞书文档。
6. 回读文档，确认 token、标题和正文非空。
7. 将任务标记为完成并保存文档 URL。
8. 返回完成结果，由事件层发送幂等回复。

### 6.3 分享式提纯服务

该服务通过 AIM 共享模型路由调用模型，不直连新的模型供应商。

固定规则：

- 删除时间戳、说话人噪声、寒暄、口水话、明显重复和残句。
- 修正常见转录错词，但不猜测无法确认的人名、公司名或数字。
- 忠实保留关键判断、论证关系、案例、数字和重要表达。
- 按少量真实主题组织小标题，小标题不得引入原文没有的结论。
- 不新增事实，不替原作者论证，不改造成营销文案。
- 不压缩成“一句话总结”或“三点启发”。

长文本按现有 `splitTranscriptChunks` 思路分块处理，再执行一次轻量合并。每块输出必须保留足够信息密度；若结果为空或相对原文短得异常，任务失败或回退到校对后的转录稿，不能交付伪摘要。

### 6.4 飞书文档

每次成功任务创建新文档，禁止覆盖旧文档。标题格式：

`【小D整理】<素材标题>`

正文结构：

1. 原始标题。
2. 来源平台与原始链接。
3. 自动整理说明。
4. 分享式提纯正文。
5. `本稿由音视频自动转录整理，涉及人名、数字和关键事实时请回看原素材核对。`

文档必须创建后回读。只有回读确认标题和正文存在，才可以向群里回复“处理完成”。

## 7. 数据与幂等

新增最小任务记录，至少包含：

- 飞书外部消息 ID，唯一索引。
- 用户 ID 和项目 ID。
- 原始链接和平台。
- 状态：`processing | completed | failed`。
- 提取记录或素材记录引用（若复用现有记录）。
- 飞书文档 token 和 URL。
- 稳定错误码与可行动错误信息。
- 创建、完成和更新时间。

收到相同消息 ID 时：

- 已完成：直接复用已保存的文档 URL。
- 处理中：不重复启动任务，只返回已在处理。
- 已失败：第一阶段不自动重试，由后续显式重试能力处理。

不得仅依赖回复接口的幂等键防止重复创建文档。

## 8. 错误处理

对外错误至少区分：

- `UNSUPPORTED_LINK`：链接或平台不支持。
- `EXTRACTION_FAILED`：素材获取或转录失败。
- `EMPTY_TRANSCRIPT`：没有有效转录文本。
- `PURIFICATION_FAILED`：模型整理失败且无法安全回退。
- `DOC_CREATE_FAILED`：飞书文档创建失败。
- `DOC_VERIFY_FAILED`：文档创建后回读不符合契约。
- `PROJECT_UNBOUND`：消息没有明确项目归属。

日志中可以记录错误码、任务 ID 和阶段，不得记录飞书 token、模型密钥或完整客户原文。

## 9. 权限与安全

- 只处理用户授权范围内可访问的公开素材。
- 不绕过平台登录、付费或访问控制。
- 飞书文档使用现有受控发布器和身份配置。
- 项目归属必须来自渠道绑定，禁止按近似名称猜测。
- 提纯稿不会自动公开、发布或进入正式知识库。
- 所有对外消息和文档写入都必须在 live 模式下执行。

## 10. 测试与验收

### 自动化测试

- 小D关键词加支持链接进入小D分支。
- 普通链接保持进入现有视频流水线。
- 显式“收选题”优先于小D关键词。
- `capture_only` 和 `evaluate` 不产生对外回复或文档。
- 提纯服务保留关键数字、案例与主要论证，不输出三点摘要式结果。
- 结果异常过短时触发安全回退或失败。
- 同一消息 ID 重放只创建一份文档。
- 文档创建后回读失败时不得回复完成。
- 各稳定错误码映射为可行动的中文提示。

### 代码层完成标准

- 相关单元测试通过。
- 飞书事件路由测试通过。
- 类型检查、Lint 和架构体积门禁通过。
- 生产构建通过。

### 真实联调标准

使用一个公开、权限明确的视频链接，在测试飞书群中完成：

1. 发送“小D，整理一下 + 链接”。
2. 收到即时状态回复。
3. 最终收到一个飞书文档链接。
4. 回读文档确认标题、来源、链接和提纯正文存在。
5. 人工抽查原视频中的关键数字、案例和判断未被遗漏或编造。
6. 重放同一飞书事件不生成第二份文档。

未完成真实飞书联调时，只能报告“代码完成”，不能报告“业务完成”或“已上线”。

## 11. 发布与回滚

本工作包不授权生产部署。代码完成后先通过本地与测试环境验收；生产上线仍需用户明确点头，并遵守仓库发布门禁。

回滚方式：关闭小D分流开关或回退本工作包提交。普通视频完整流水线保持独立，因此回滚小D能力不应改变现有视频处理行为。

## 12. 后续候选，不在本期实现

- 飞书音视频附件上传。
- 多链接批量处理。
- 长任务持久队列和进度卡片。
- 用户确认后“一键沉淀为项目知识”。
- 对提纯稿继续执行选题或内容改写。
