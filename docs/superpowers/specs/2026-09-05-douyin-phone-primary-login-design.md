# 抖音扫码登录：手机号主账号设计

## 目标

在 AIM 登录页增加抖音扫码登录。手机号仍是唯一主账号标识；抖音只用于快捷验证和登录，不单独创建无手机号账户。

## 用户流程

1. 用户在登录页选择“抖音扫码登录”。
2. 服务端生成一次性 `state` 并跳转至抖音授权页，请求 `user_info`。
3. 抖音回调后，服务端以 `openid` 查询已绑定账号：
   - 已绑定：创建 AIM 用户会话，跳转首页。
   - 未绑定：跳转手机号验证页。
4. 未绑定用户输入手机号并完成短信验证码：
   - 手机号已有 AIM 账号：将该抖音 `openid` 绑定到该账号，然后登录。
   - 手机号不存在：创建手机号账号、绑定该 `openid`，然后登录。
   - 该 `openid` 已绑定其他账号，或手机号已绑定不同抖音账号：拒绝绑定并给出清晰提示。

## 数据与安全约束

- 手机号是账户唯一标识，保持现有唯一约束。
- 一个抖音 `openid` 至多绑定一个 AIM 用户；一个 AIM 用户可以绑定多个抖音号。
- 扫码登录使用独立的 OAuth `state` Cookie，不能复用“登录后同步抖音数据”的 state。
- `ClientSecret` 仅在服务器端换取令牌，绝不发送至浏览器。
- 不保存用于登录以外用途的抖音令牌；内容数据同步仍使用现有的“登录后绑定抖音”流程。

## 界面

- 登录页新增“抖音扫码登录”按钮，位于现有手机号验证码登录的替代入口。
- 首次扫码后显示“绑定手机号”页，说明手机号用于账号识别和找回。
- 绑定完成后回到 AIM 首页；失败时回到登录页并展示一次性错误提示。

## 验收条件

- 已绑定手机号和抖音的用户扫码后可直接登录。
- 未绑定抖音的扫码用户必须完成手机号验证码验证，不能绕过。
- 新手机号会创建一个以手机号为主标识的 AIM 用户。
- 同一 `openid` 及手机号都不能绑定至多个 AIM 用户。
- 原有密码登录、短信登录和登录后抖音数据绑定不受影响。
