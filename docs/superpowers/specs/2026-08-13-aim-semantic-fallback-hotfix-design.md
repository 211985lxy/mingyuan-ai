# AIM 明确创作指令语义兜底设计

## 问题

线上请求“参考这个给葛老板写一个”已经进入内容生成链路并携带参考原文，但语义理解模型连续没有输出内部标签，系统以“语义理解协议不完整”终止。内部协议因此错误地拥有了否决清晰用户指令的权力。

## 设计

- 保留语义理解模型和一次格式修复，用于普通复杂请求。
- 两次协议解析都失败后，仅对确定性的完整内容创作请求降级继续。
- 确定性判断只识别“创作动作 + 完整内容对象”，例如“写/生成/创作/仿写 + 文案/口播/文章/脚本/内容/一篇/一个/一版”。
- 降级结果固定为 `handling: deliver`，任务简报直接采用用户原话，不猜人物、行业、结构或额外要求。
- 分析问句、局部修改、无法判断的请求仍失败或澄清，不一律强行生成。

## 验收

- “参考这个文案给罗老板写一个新的文案”在两次协议无效时返回 `deliver`，brief 保留原话。
- 线上真实变体“参考这个给葛老板写一个”在有参考材料时同样继续生成。
- “这个文案是什么结构”不能触发创作兜底。
- 正常协议和协议修复路径保持不变。
