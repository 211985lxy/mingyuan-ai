## Why

当前视频创建链路虽然已经有“选结构、选模板、生成文案、生成视频”的外形，但系统内部仍然把导演决策、编剧决策和视频包装决策混在一起。结果是结构不会真实约束文案，爆款模板不会真实驱动表达，闪剪模板也没有成为真正的包装层，用户最终拿到的只是“说一句话的数字人口播”，而不是可控的营销短视频。

产品现在已经接近上线，数字人克隆、声音克隆和视频生成又是最核心的交易链路。如果我们不先把视频创建中枢固化成清晰的三层模型，后续无论补 prompt、补模板还是补素材上传，都会继续在错误的抽象上堆复杂度。

## What Changes

- 将视频创建中枢正式固化为三层模型：导演层（视频结构）、编剧层（内容模板与 brief）、包装层（闪剪模板与素材混剪）
- 新增一套可复用的视频结构系统，用结构蓝图约束后续文案生成与视频任务追踪
- 扩展文案生成链路，让脚本生成同时使用 IP 档案、结构蓝图、内容模板、当前视频 brief，并建立质量门槛与评分排序
- 新增视频包装规划能力，将闪剪模板、素材位、BGM、字幕/贴片规则、画中画类能力收口到正式的包装层，而不是散落在临时参数里
- 重构 `/create` 规范，从“内容优先”升级为“结构 -> 表达 -> 包装 -> 出视频”的三层式创作流程
- 要求最终视频任务能够追溯自己使用了什么结构、什么脚本模板、什么包装模板、什么素材组合

## Capabilities

### New Capabilities

- `video-creation-workbench`: 定义 `/create` 作为三层创作工作台的职责，包括状态编排、草稿恢复、依赖失效提示和最终生产总览
- `video-structure-system`: 定义导演层的视频结构模板、结构蓝图和结构追踪规则
- `video-packaging-pipeline`: 定义包装层的闪剪模板选择、素材/BGM 规划、包装能力展示和任务映射规则

### Modified Capabilities

- `content-generation-pipeline`: 文案生成从“模板 + brief”升级为“结构 + 模板 + IP 档案 + brief”，并增加质量门槛与候选评分
- `content-first-journey`: `/create` 流程从文案优先升级为三层式创作流程，要求用户先定结构、再定表达、再定包装，最后生成视频
- `frontend-real-api-runtime`: `/create` 运行时必须彻底脱离 mock service，改为使用真实结构、模板、脚本、包装和任务 API

## Impact

- **前端创建流程**: `apps/web/src/app/(dashboard)/create/page.tsx` 的步骤定义、表单采集、引导文案和任务提交方式都需要重构
- **前端运行时**: `/create` 不再允许依赖 `@/lib/mock/services` 生成结构、模板、文案或任务占位结果
- **后端 API**: `/api/scripts/generate`、`/api/tasks` 需要扩展结构与包装参数；新增结构列表、包装模板与生产计划相关接口
- **数据模型**: 需要引入结构模板、包装模板/缓存、视频生产计划与更完整的生成追踪字段
- **闪剪集成**: 需要正式利用 `GET /v1/clip/template`、`GET /v1/clip/template/detail/{id}` 以及 `virtualman_broadcast` / `custom_virtualman_broadcast` 的包装参数，而不是依赖硬编码 `styleId`
- **产品体验**: `/create` 的专业引导文案、素材策略和质量验收逻辑将成为主链路，不再允许只是“走完流程”
