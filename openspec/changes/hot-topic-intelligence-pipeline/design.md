## Context

现有热榜数据来自真实抓取，但只保存了标题、热度、排序和封面。创建页文案“选择热点后，AI 会自动将文案与当前热点事件关联”与真实实现不符，因为后端只把 `hotTopic` 标题拼进 prompt。系统没有事实检索、没有相关性判断、没有风险拦截、也没有生成时热点快照，导致输出不可解释、不可审计、不可控。

该改造必须满足三个约束：
- 不能引入 mock 或伪造热点上下文
- 不能显著拖慢 `/create` 的主链路
- 必须保留当前三层视频创建架构，不与正在收尾的其它 change 冲突

## Goals / Non-Goals

**Goals:**
- 选中热点后，系统基于真实公开搜索结果生成结构化热点洞察
- 在生成文案前，系统给出热点与本次营销视频的适配度判断和借势建议
- 文案生成使用结构化洞察而不是裸标题，低相关热点自动降级为弱关联或不强行引用
- 热点洞察与适配结论落库，后续可追踪某次文案为何这样生成
- 用户在 `/create` 中能看懂“热点是什么、为什么火、为什么和我有关或无关”

**Non-Goals:**
- 不做全量 Top 50 热点预分析
- 不引入新的付费搜索 API 或外部向量数据库
- 不做热点效果归因报表
- 不自动替用户决定最终一定要追哪个热点

## Decisions

### D1: 用真实公开搜索摘要做热点事实输入，而不是让模型裸猜

**选择**: 服务端通过 Bing RSS 搜索结果抓取热点相关的真实标题、摘要、链接和发布时间，再交给 LLM 生成结构化热点洞察。

**备选方案**:
- 直接让 LLM 根据热点标题自行理解：实现最简单，但本质是猜测，无法满足“查一下这个热点是怎么回事”
- 继续只依赖热榜源字段：当前热榜源没有事件摘要，信息量不够
- 引入新的付费 SERP API：更稳，但上线成本和密钥管理更重

**理由**: Bing RSS 是公开、结构稳定、可直接服务端抓取的真实结果源，足以提供事实线索，而且不需要新依赖或密钥。

### D2: 热点洞察按需分析并缓存到 `DouyinHotItem`

**选择**: 用户选中某个热点时才触发分析；分析结果和搜索快照回写到该 `DouyinHotItem` 记录。

**备选方案**:
- 每小时对 Top 50 全量分析：成本高、延迟大，很多热点根本不会被用户点
- 新建独立洞察表：隔离更强，但当前阶段会放大 schema 和查询复杂度

**理由**: 绝大多数热点不会进入实际创作。按需分析可以把真实成本集中在用户真正选择的热点上，并且依旧能缓存复用。

### D3: 区分“通用热点洞察”和“本次创作适配结果”

**选择**:
- 通用热点洞察存到 `DouyinHotItem`
- 本次创作的适配判断存到 `ContentGenerationRun`

**备选方案**:
- 把两者都塞进 `DouyinHotItem`：会把不同用户、不同模板、不同 brief 的判断混在一起
- 把两者都即时计算不落库：无法复盘、无法审计

**理由**: 一个热点本身的事实解释是共用的，但“是否适合借势”是与用户和当前创作上下文强相关的。

### D4: 对低相关热点采取“软拦截 + 生成降级”，而不是一刀切报错

**选择**: 当适配度低时，前端显式预警，后端文案生成不强制引用热点标题，转为“价值观映射 / 借题发挥 / 业务观点”策略。

**备选方案**:
- 直接拒绝生成：太生硬，会打断用户探索
- 继续照常生成：等于默认硬蹭

**理由**: 系统应该像营销总监一样阻止用户犯错，但不该把用户卡死。最优做法是降级策略而非沉默放行。

### D5: `/create` 中把“追热点”升级成“借势建议”

**选择**: 创建页增加两张卡片：
- 热点理解卡：这件事是什么、为什么火、哪些角度不能碰
- 借势建议卡：和你这条视频的相关度、建议角度、建议开场、风险提示

**备选方案**:
- 只在脚本结果里隐式体现：用户无法在生成前判断是否值得追
- 单纯展示一个相关性分数：不够可解释

**理由**: 用户需要的是营销判断，不是分数本身。系统必须解释“为什么”。

## Risks / Trade-offs

- **搜索结果偶发噪声** → 通过多条结果聚合、保留来源链接、让 LLM 以“信息不足时保守输出”为规则降噪
- **首次分析增加等待时间** → 仅在用户选中热点后触发，且结果持久化缓存；热点切换时展示加载态
- **信息过时** → 使用 `fetchedAt` 与搜索结果发布时间生成 freshness 提示，超过阈值则给“可能已过时”提示
- **敏感热点借势失当** → 洞察输出风险等级和不建议角度；低相关或高风险时前端显式警示，后端降级生成
- **外部搜索源不可用** → 洞察接口返回“暂时无法完成热点理解”，不再伪装已理解；用户仍可选择不追热点继续生成

## Migration Plan

1. 扩展 Prisma schema，为 `DouyinHotItem` 和 `ContentGenerationRun` 增加热点洞察/适配字段
2. 实现热点搜索、洞察、适配服务与新 API
3. 改造 `/create` 热点选择体验与 `scripts/generate` 入参
4. 用真实热榜数据执行端到端验证：热点选择 → 洞察 → 适配 → 文案生成
