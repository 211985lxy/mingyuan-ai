## Why

当前“追热点”流程只把热榜标题当作一个字符串注入文案生成，系统不会真实理解热点事件，也不会判断它与用户业务是否相关。这会导致硬蹭、幻觉式解读和低转化文案，直接伤害用户对产品“像有营销总监在旁边指导”的信任。

## What Changes

- 新增热点理解能力：用户选中热点后，系统基于真实公开搜索结果生成事件摘要、爆火原因、营销母题和风险提示
- 新增热点适配评估能力：系统结合 IP 档案、内容模板、Brief 和视频结构，评估该热点是否适合借势，并给出关联理由、建议角度和注意事项
- 改造文案生成链路：脚本生成不再只接收 `hotTopic` 标题，而是使用结构化热点洞察与适配结果，避免硬蹭和生搬硬套
- 改造 `/create` 体验：热点选择后展示“热点是什么”“为什么火”“怎么和这条营销视频相关”，并在相关性低时显式预警
- 新增持久化审计能力：把热点洞察快照与本次生成时的适配判断保存下来，便于复盘和优化
- 新增热点新鲜度与风险控制：过期热榜、信息不足或高风险热点不得再伪装成“AI 已自动关联”

## Capabilities

### New Capabilities
- `hot-topic-intelligence`: 热点事实检索、结构化事件理解、业务借势适配评估、风险与新鲜度判断

### Modified Capabilities
- `content-generation-pipeline`: 文案生成从“标题注入”升级为“基于热点洞察与适配结论的受控生成”，并持久化生成时使用的热点快照
- `content-first-journey`: `/create` 流程在热点步骤中展示热点理解卡和借势建议卡，对低相关热点给出明确预警与降级引导

## Impact

- **代码**: 新增 `lib/hot-topic-intelligence.ts`、热点洞察与适配 API 路由、创建页热点洞察 UI；修改 `scripts/generate`、`douyin-hot`、`types/api`
- **API**: 新增热点洞察接口与热点适配评估接口；修改 `POST /api/scripts/generate` 入参与返回数据
- **数据库**: 扩展 `DouyinHotItem` 与 `ContentGenerationRun` 的热点洞察/适配快照字段
- **外部系统**: 使用真实公开搜索结果源补充热点事实，不允许 mock 或静态示例数据
- **用户体验**: “追热点”从热词入口升级为“借势建议”能力，系统必须告诉用户为什么该追或不该追
